Do group consecutive turns with 4pt gap, 12pt between speakers. Do not tint bubbles with bot colors; the bot avatar carries identity.

Composer

GLASS

Purpose. Floating input above the thread. Replaces thread-composer.tsx, composer-reply-preview.tsx, reply-dismiss-button.ios.tsx.

Anatomy: one glass capsule: radius 26, min height 52, 4pt inset on all sides so the 44pt controls inside are concentric (26 - 4 = 22). Inside, left to right: 44pt Attach (plus, bare, no extra glass), the text (16pt; grows to 6 lines, then scrolls) and the 44pt trailing control. Attach stays at the bottom edge as the text grows. Chip row (32pt chips) sits inside the capsule above the text.

Trailing control: empty = Dictate (mic, bare, no extra glass inside the capsule); text present = Send (arrow.up); agent running = Stop (stop.fill) in the same slot. The trailing control is prominent (fill rgba(241,240,235,0.92), ink glyph) only when no approval card is pending. While any card is pending it uses the solid neutral fill #33322F with an ink glyph, so the card Send is the only tinted action. This is decided by thread state, not scroll position. Stop rule: Stop keeps the trailing slot for the whole run; typed text stays as a draft and Send returns when the run ends or is stopped. Stopping shows a 20pt spinner in the slot, disabled, for up to 3 s; on failure the slot returns to stop.fill and the working indicator stays. Nothing sends automatically. No caption shows while typing during a run. Dictating shows a Stop control (stop.fill) in the slot. Send is disabled with no text and no attachment.

Reply preview: glass strip above the capsule, radius 20, bar + name + snippet + optional thumbnail + dismiss (xmark.circle.fill, 24pt visual in 44pt target; native button on iOS).

Mention popover: typing @ opens a glass list above, radius 22, rows 44pt with MentionOptionIcon (28pt bot letter tile, or person.fill circle for teammates), name, role; first row selected. Dismiss on Escape, tap away, or deleting the @.

Do not stack the popover and reply preview; the popover replaces the preview position while open. Keep one prominent button. Composer rises with the keyboard and the home indicator inset.

Mail approval card

CONTENT

Purpose. The agent drafted an email; the user decides. Replaces apps/web MailApprovalCard.tsx for mobile thread.

Anatomy: card fill, 1px border, radius 20. Header: subject (600, one line) and status at right. Rows: To, optional Cc (labels 20pt wide, mutedForeground), body 14pt/1.45. Footer actions only in Needs approval.

Status: Needs approval (a 22pt tinted pill, the same as the thread card: warning #E9C46A on 16% warning, 12pt/600; light mode #7A4E0B on 12% #B7791F, 4.5:1 or better), Sent (success #4ECB71 plus checkmark), Not sent (mutedForeground plus xmark). Color is never the only signal; the word is always present.

Actions: Edit (solid secondary fill, 96x44pt: dark #33322F, light #E2E2DC, no glass) and Send (prominent tinted capsule). One prominent per card. Card Send is the only tinted action while pending. Sending requires a tap; there is no auto-send. After Send, actions are removed and status flips to Sent. The card body is one tap target that opens the same editor as Edit. The draft is autosaved, so there is no Save. The card, the Edit sheet and Compose X Save draft are the same draft record. States: Needs approval, Needs approval with Cc, Replaced (collapses to one muted row, Replaced by a newer draft, no buttons), Sent, Not sent, empty recipient (To reads Add a recipient in warning color, Send dimmed), Updating (Edit dimmed while the agent revises).

Layers: card is content, and so are its buttons: glass belongs only to the floating navigation and controls layer, so card buttons use a solid secondary fill (dark #33322F on #ECEBE6 text, light #E2E2DC on #1A1A1A text) and the one primary action is the solid ink pill. Do not show Send when there is no recipient.

MCP tool approval, Ask card, Choice card

CONTENT

Purpose. The agent pauses for a decision. Replaces McpApprovalCard.tsx, AskActions.tsx, ChoiceCard.tsx and AskBlock in thread.tsx (web: AskCard.tsx).

MCP approval: letter tile (integration agents, no logos), a plain-language title (14pt), then for money the amount as the largest text on the card (34pt/600, tabular), then the other arguments in an inset well (#1C1C1A, radius 14, 13pt, max 4 lines). The tool name is never shown on the card; it appears only in the Settings details. Actions stacked, full width, 44pt: Allow once (prominent), Deny (solid secondary fill, destructive text). Always allow (secondary fill, between Allow once and Deny) appears only for read-only tools such as Search mail. Choice card: radio rows (min 56pt, radius 14, accent fill, selected = 1px primary border and filled radio) then one prominent Continue. Disabled until a row is selected. While submitting, the tapped button shows a spinner and all others disable.

Error: failed submit shows a native alert (Could not submit answer) and re-enables. Resolved: card collapses to one line, e.g. Allowed once.
