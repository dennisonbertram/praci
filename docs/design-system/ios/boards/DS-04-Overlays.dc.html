Sheets and overlays
Sheet, alert, action sheet, context menu, menu, popover, toast, search overlay, organize and member pickers, select text, scrim. Outer display 466x678 (side strip at left), inner display 890x626 (fold x 435-455). Dark mode unless marked.

Sheet: medium and large detent

Purpose. A short task or detail view over its parent. Modal; the parent is dimmed.

Anatomy. Grabber 36x5pt, 6pt from top. Content cards sit inside with 14pt inset.

Size. Inset 8pt from the device edge, radius 34pt (device corner 42 minus 8 inset, concentric). Medium detent top at about 50% height; large top at 12pt. Card radius 20pt (34 minus 14).

Layer. Glass at medium (regular, 74% fill). Large detent is nearly opaque (97% fill) because it holds a lot of text. Rows are content: #2A2927, never glass.

States. Drag grabber or scroll to expand; tap grabber cycles detents; swipe down dismisses.

SF Symbols. chevron.right (row disclosure), pin, bell.

Replaces. RN Modal with presentationStyle pageSheet in apps/mobile/components (select-text-sheet.tsx and the organize modal).

Do keep one sheet at a time. Don't put glass rows inside a glass sheet.

Unconfirmed: on the Duo outer display I keep the sheet to the content area beside the side strip so the Island stays clear.

Sheet with header

Purpose. A form or choice that is saved or abandoned: X leading, title center, Create or Save trailing.

Anatomy. Header 52pt. X is a 44pt glass circle; Create or Save is a text capsule, 44pt tall, 18pt side padding, 17pt text. Title 17/600. The text capsule is the one prominent (ink) control.

States. Create dimmed (40% opacity) until the form is valid. Second step swaps X for Back. Never show X, Back and the text capsule together as three controls. A read-only sheet shows Done alone.

Layer. The X is glass floating over the sheet body; the body is content.

SF Symbols. xmark (X), chevron.left (Back).

Replaces. apps/mobile/components/sheet-header.tsx (cancelHeaderOptions and its Done counterpart, native bar-button items on iOS 26).

Don't use the header as a page title with no way to dismiss.

Alert

Purpose. A decision that needs an answer now. Title question, one line of consequence, two buttons.

Anatomy. 270pt wide, radius 26pt, regular glass (alerts carry text, so never clear). Body padding 22/20/18. Buttons 48pt tall, hairline dividers. Cancel always present; the safe choice is bold.

Confirm. Action button is bold, ink color.

Destructive. Destructive button uses the destructive token (#F46262) at regular weight; Cancel is bold. Never preselect the destructive choice.

Placement. Centered in the content area on the outer display; moved to the trailing pane on the inner display (see fold section).

Scrim. System dim, 40% black.

Replaces. Native Alert.alert; web counterpart packages/ui-web alert-dialog.tsx.

Unconfirmed: exact corner radius and width of the iOS 26 alert; 26pt and 270pt are my estimate.

Action sheet, inline

Purpose. Choose among actions for something the person just did, such as leaving a draft with unsaved changes.

Anatomy. Glass panel, radius 22pt, 250pt wide, anchored 8pt above the control that opened it, left edges aligned. Optional 13pt muted title. Rows 44pt. Destructive row in #F46262. No Cancel row; tapping outside dismisses.

Scrim. Light dim, 20% black, so the source control stays readable.

Layer. Glass over content.

SF Symbols. trash, square.and.arrow.down.

Replaces. ActionSheetIOS on mobile; web dropdown-menu.tsx for the same job.

Context menu on a message

Purpose. Long-press a message for actions on it.

Anatomy. The pressed bubble lifts (scale 1.04, larger shadow) and stays in place; the rest of the screen blurs 14pt and dims 30%. Menu glass, radius 22pt, 250pt wide, 8pt below the bubble, aligned to the bubble edge nearest the screen edge. Rows 44pt, label leading, SF Symbol trailing. Destructive row last, after an 8pt divider.

Items. Reply, Copy, Select text, Pin, Delete.

SF Symbols. arrowshape.turn.up.left, doc.on.doc, character.cursor.ibeam, pin, trash.

States. Default; pressed (white 10% row fill); destructive; disabled (40%).

Replaces. apps/mobile/components/message-context-menu.tsx (MenuView, shouldOpenOnLongPress); the system draws it.

Do keep the bubble readable and unclipped. Don't add a custom lift preview; the system provides it.

Menu from a glass button

Purpose. The overflow (More) and sort/filter menus that hang off a toolbar button.

Anatomy. Glass panel, radius 22pt, 260pt wide, 8pt gap from the source button. Opens toward the content: on the outer display the trigger is in the side strip, so the menu opens to the trailing side with its bottom edge aligned to the button. Sections separated by an 8pt divider and an optional 13pt muted header. Rows 44pt. A checkmark in a 20pt leading column marks the selected option; icon items keep the symbol trailing.

States. Source button held in a pressed fill (white 12%); row pressed; selected; destructive; disabled.

SF Symbols. ellipsis, checkmark, checkmark.circle.

Replaces. Native menus (MenuView / Expo UI Menu); web dropdown-menu.tsx.

Do use a checkmark for single choice, one per section. Don't nest a menu inside a menu.

Popover (inner display)

Purpose. A small, nonmodal control panel next to its trigger, such as inbox filters. Inner display only; on the outer display the same content is a medium-detent sheet.

Anatomy. Regular glass, radius 22pt, 300pt wide, 12pt inner padding, opens 8pt from its source, top edge aligned with the button. No scrim; the parent stays live and tappable, tapping outside dismisses. Switch rows 44pt.

Placement. Stays in the trailing pane. A trigger in the leading (sidebar) pane opens its popover to the right of the fold, not across it. Filters: Needs reply, Newsletters, Read mail, then Important only; the outer display shows the same rows in a medium-detent sheet.

SF Symbols. line.3.horizontal.decrease, magnifyingglass, square.and.pencil.

Replaces. packages/ui-web popover.tsx and tooltip.tsx for the equivalent web surfaces.

Unconfirmed: whether iOS 26 popovers draw an arrow. I draw none.

Toast and notification banner

Purpose. Tell the person something finished or failed without taking their place. Banners never block input outside themselves.

Anatomy. Glass capsule, radius 26pt, 12pt padding, 12pt from the top of the content area. 36pt identity tile (shipped agent avatar, or a neutral tile when a message is waiting to send), title 15/600, one body line 13pt muted. A trailing action capsule appears only when the person can fix the problem.

Behavior. One at a time, newest replaces older. Success banners dismiss on their own after about 5 seconds (proposal); Waiting to send stays until the message goes out, then dismisses itself. A message that finally fails shows Retry on the message in the thread, not here. Tap opens the source chat. Announced as a polite live region; errors as assertive.

Scrim. None.

SF Symbols. clock, exclamationmark.triangle.

Replaces. apps/web notification-toaster.tsx; mobile uses the system notification banner for background and an in-app banner in the foreground.

Command and search overlay

Purpose. Global Search across agents, mail and artifacts from anywhere. Web equivalent is the command palette.

Anatomy. Custom full-screen overlay, so it uses the overlay token (#080807 at 72%) over the blurred app. Search field is a glass capsule, 44pt, with a magnifyingglass and a text Cancel button. Results are content rows on the overlay (no glass, no cards): 36pt tile, title 15/500, secondary line 13pt muted, grouped under 13/600 muted headers Agents, Mail, Artifacts. The matched text is semibold.

Opening a result. A mail hit opens the message and scrolls to the matched text. A chat hit opens the thread scrolled to that message and briefly highlights it. Back returns to the results.

On the outer display the field sits right of the side strip; the keyboard rises from the bottom and results scroll above it. On the inner display it is a 400pt panel in the trailing pane (below), never across the fold.

States. Empty query (recent searches), typing, results, no results, loading (shimmer rows from apps/web/src/components/ai).

SF Symbols. magnifyingglass, envelope, doc.text, person.crop.circle.

Replaces. packages/ui-web command.tsx and dialog.tsx.

Agent organize modal and member picker

Organize. Per-agent actions in a medium-detent sheet. Agent name title; actions Pin, Silence notifications, then "Move to" section list with a checkmark on the current section (current row disabled), then New section and Rename section. Cancel is a full-width secondary capsule at the bottom. New and Rename swap the action rows for a name field with Create or Save.

Member picker. Large sheet with header X / New group / Create. Rows 56pt: 34pt agent avatar (identity color), name 16pt, switch trailing. When 6 members are chosen (the group maximum) unselected rows disable and a 13pt muted line says why.

Layer. Sheet glass or opaque as in the detent rules; rows are content.

SF Symbols. pin, pin.slash, bell, bell.slash, folder.badge.plus, pencil, checkmark.

Replaces. the organize modal and member picker in apps/mobile/components. Today organize is a custom overlay with its own scrim; this specs it as a native sheet.

Select-text sheet

Purpose. Lets people select part of a message, which a chat bubble cannot do directly. Opened by Select text in the context menu.

Anatomy. Large detent sheet, opaque fill, grabber. Done only, trailing, prominent (read-only, nothing to cancel). Body is selectable text, 16/24 on the sheet, 20pt side padding, 40pt bottom padding, the whole message as one block so a selection spans paragraphs. System selection handles and edit menu (Copy, Share, Look Up).

States. Default; active selection (selection tint #4F8FF7 at 30%); long message scrolls under the header.

Replaces. apps/mobile/components/select-text-sheet.tsx (Modal pageSheet).

Do keep text in the content layer, no glass behind it.

Scrim and overlay token

Token. overlay from packages/ui-tokens: dark rgba(8,8,7,0.72), light rgba(20,20,22,0.45). One value per mode; do not hardcode a dim.

Rule (proposal). Native system presentations (sheet, alert, menu, action sheet) use the system dim, which I draw as 40% black, and are never re-dimmed by us. The overlay token is for surfaces we draw ourselves: search overlay, any custom full-screen modal. Toasts, popovers: no scrim.

Context menu adds a 14pt blur on top of a 30% dim.

Clear glass over media needs a 35% dark layer (Apple); not used by these overlays.

Unconfirmed: the exact dim iOS applies. 40% is my approximation.

Where overlays sit on the inner display

Rule. Nothing interactive crosses the fold (x 435-455, active when half-folded). Alerts, menus, popovers and search panels are placed in the trailing pane (x 455-890) so the system never centers them on the hinge. The dashed outline shows where a default-centered alert would land.

Sheets. A form sheet is capped to the trailing pane width (about 420pt); a large sheet is allowed to span both panes only when the device is flat, and its header and buttons stay in the trailing pane.

Menus from the leading pane flip toward the trailing side and start right of the fold.

Toasts align to the trailing pane top.

Unconfirmed: this is design intent for the Duo; I could not confirm that the platform reflows system alerts away from a fold on its own. Treat it as a requirement on our custom placement code, with a drawn fallback: when the system alert would cross the fold, show our own alert view centered in the trailing pane.
