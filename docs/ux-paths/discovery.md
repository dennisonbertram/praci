## Application Type
Multi-agent AI workspace for running a startup. Chat with "bots" (Chief, Inbox agent, Legal agent, Carta/Finance agents, user-made bots), plus first-class pages: Inbox (Gmail), Finance, Legal, Cap table, Contacts, Data room, Artifacts. Delivered as a web SPA, an Electron desktop shell that hosts the same web UI (and can start a local Docker stack), and an Expo mobile app (smaller; no Legal/Cap table/Data room).

## Tech Stack
- Web: React + react-router (`apps/web/src/App.tsx`), Lingui i18n (`<Trans>`, `t`), `@rakazo/ui-web`, Tailwind container queries. Shell is `apps/web/src/pages/Shell.tsx` (very large) with extracted `pages/shell/{composer,transcript,bot-panel,command-palette,bot-picker,BotSkillsSection}.tsx`.
- API: oRPC router `apps/api/src/router.ts`, contracts `packages/contracts/src/*.ts` (`rpc.ts`, `inbox.ts`, `data-room.ts`, `contacts.ts`, `sidebar-pages.ts`), agent tools `packages/adapters/src/builtin-tools.ts`, approvals `packages/adapters/src/approval-ask.ts`, mail sync/triage `packages/adapters/src/`, Prisma in `packages/db`.
- Desktop: `apps/desktop/src` (`main.ts`, `setup.html`/`setup.js` first-run window, `local-stack.ts`, `auto-update.ts`).
- Mobile: `apps/mobile/app/*.tsx` (expo-router).
- E2E specs: `apps/web/e2e/*.spec.ts`. Stories next to components. Demo stack: `packages/testkit/src/cli/demo`.

## User Roles
- Signed-in member of a space (default role). One personal space; multiple spaces possible (`New space`).
- Deployment owner (`isDeploymentOwner`): sees Settings > "Bots run on" (only on Docker sandbox + desktop app), "Server integrations", Updates, Computer sections; is the person onboarding "Connect your apps" configures providers for.
- Subscriber vs not: paywall (`SubscriptionGate`) when billing is enabled; `billingEnabled` is false for the deployment owner (`router.ts` me: `Boolean(deps.billing) && !actor.isDeploymentOwner`).
- Variants that change screens: no model connected (`me.needsModel`), AI data consent off, no Gmail, Gmail needs reconnect, Carta connected/expired, desktop vs browser, phone width (drawer sidebar, collapsed panels).

  - After sign-in: "Signed in with {provider}" (role status) and the Continue button enables (`canSaveModel`).
  - "Use an API key instead" `<details>` (collapsed): Provider select, Model select / "Other model..." for OpenAI-compatible, optional Account ID + Gateway ID (Cloudflare AI Gateway), thinking-level select, "API key" (or "Or paste an API key" for providers that also have sign-in), connection test button (disabled until key >= 8 chars), OpenAI-compatible base URL probe. Errors in red under the section; notice in green.
  - "Continue" saves the model.
  - Auto-skip: if the server already has a default model, the step is skipped (`onboarding-model-auto-skip.spec.ts`).
- **Integrations step** = "Connect your apps" (`components/integrations/ConnectAppsStep.tsx`), shown only when `integrationSetup.needsSetup`. ## State transitions
- Onboarding: loading -> model (if needsModel) -> integrations (if needsSetup) -> bot -> /app/:botId. Skip paths: model auto-skip when a default exists; "Skip for now" on apps.
- Model sign-in: idle -> pending (popup/tab) -> waiting (code paste / device code / expiry countdown) -> "Signed in with X" -> Continue; Cancel or popup closed returns to idle; error text under the section.
- Tour: hidden -> open (new user with bots, or "Take the tour") -> steps -> finish saves `tourSeen`.
- Data room item: uploaded -> reading -> indexing -> tagging -> ready; or failed ("Couldn't read this file", Try again) / not searchable ("Too large to search inside"). Zip: opening -> found N -> adding X of N -> reading -> done / zip failure reasons.
- Export: none -> pending/running (poll) -> ready (expires) -> new request after expiry.
- Mail: cached 14-day window; triage pending -> sorted; Cleanup actions are logged with Undo; spam <-> not spam sticky.
- Skill draft: agent-written draft -> Approve (becomes a skill) / Discard.
- Run location: bot inherits deployment default until its own "Runs on" differs.
