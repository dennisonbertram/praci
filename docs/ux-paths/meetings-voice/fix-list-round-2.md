# Fix list, round 2: Granola and Wispr Flow plans and mockups

Date: 2026-10-20

This list merges the three round-2 reviews of the Granola plan (`docs/plans/granola.md`, epic #444), the Wispr Flow plan (`docs/plans/wispr-flow.md`, epic #452) and the two mockups (`docs/granola/mockup.html`, `docs/wispr-flow/mockup.html`). Nothing is built, so every row changes a plan or a mockup. It builds on the round-1 list, `docs/ux-paths/meetings-voice/fix-list.md`; round-1 row ids are written FX-n.

## Sources and reviewer keys

- flow = `docs/ux-flow/meetings-voice/round-2/report.md` (N1 to N7).
- walker = `docs/ux-walker/meetings-voice/round-2/STORY-*/findings.json` (F2-... are new; F-... are round-1 items still open).
- visual = `docs/ux-visual/meetings-voice/pages/{granola-desktop,inbox-and-flow,mobile}/findings.md` (GD, IB, SV, CL, CS, TK, FM, XS and M ids). Visual severity P1 is written high, P2 medium, P3 low.
- The "Source ids" column lists each id, then the reviewers who found it in brackets. Where visual lists "own, muse, argon", the bracket reads visual (own, muse, argon).

## Decisions that stand

- D1 to D4 from round 1: S7 (#443) deferred; one Granola agent; Flow is a Transcribe only row in the Voice providers list with consent at Connect; the person who connected can delete a stored meeting with its to-dos.
- Earlier decisions: Business and higher API sync, meetings private to the connecting user, follow-ups as Inbox to-dos now, Flow slices #447 and #448 blocked on API access.
- Round-1 rejected rows (FX-34 to FX-39, FX-51, FX-52, FX-62, FX-63) stay rejected. Where a round-2 finding repeats one, the row below is rejected and cites the FX id. Two round-1 rows are changed on new evidence, and each says so: FX-26 (RX-4) and FX-61 (RX-8).

## Defaults applied

These are the defaults the maintainer asked for. Each row that uses one names it.

1. Granola consent is asked at Connect with one sentence under the button, matching Flow. A meeting-only user never sees the mail-worded Inbox prompt.
2. The Flow consent sentence drops "text near the cursor".
3. The Disconnect copy states that Rakazo keeps the meetings and to-dos.
4. The delete confirmation names the meeting and says Granola's note is untouched.
5. `needs_reconnect` gets a defined tile and card status that is not a green "Synced".
6. After Connect, the provider list shows which provider transcribes.
7. At the daily cap, the call card says typing still works.
8. On mobile only the checkbox completes a to-do; the row does not.
9. The MCP sign-in is drawn above the key card.
10. The "From:" prefix is removed everywhere.
11. Contrast is at least 4.5:1 for text, dark-mode checkboxes show an outline, and targets are at least 32 px (44 pt on the phone).
12. Phone frames match the real `SettingsGroup`: title-case headers, rows of 52 pt or more, a `NativeActionButton`.

Proposed strings in the rows are drafts. The PR that builds each one quotes the final text and argues it, as `AGENTS.md` requires.

## How to read the list

- Rows are grouped by target so that three editors can work in parallel: A (Granola plan), B (Wispr plan), C (Granola mockup), D (Wispr mockup). The two plan editors each own one plan file; the mockup editors each own one HTML file. Group E holds the one item that belongs to none of the four files. Rejected rows come last in each group.
- Journeys use the story ids of the catalog: GS (Granola setup), IF (Inbox follow-ups), MB (mobile), MX (cross-surface), WF (Wispr Flow).
- Status is `open` (an editor applies the change) or `rejected` (the reason is in the row).
- Where a row says "no new string", the PR must not add copy.
