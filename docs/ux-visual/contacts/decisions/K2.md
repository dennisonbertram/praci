# K2: Undo goes through the one app toaster

**Decision: B (Restructure), with the shortened failed-restore copy grafted from C.** Remove the separate sticky notice. The delete Undo becomes an action toast in the shared Base UI `NotificationToaster`:
- an `action` field on the toast data, rendered as a primary `Button size="sm"`;
- the toast's close X replaces Dismiss;
- `timeout: 0` while Undo is offered;
- toasts with an action sort to the front;
- `line-clamp-2` on the title;
- `pointer-coarse:` 44px targets.

"Restored <name>" is a normal timed toast. A failed restore reads "Could not restore <name>" and offers a "Try again" action.

**Defense.**
- B removes the root cause: two independent transient surfaces sharing the screen edge. A and C keep two systems apart only by pixel offsets, and those break silently if the toaster offset ever changes.
- B also fixes F26: Undo is no longer lost on navigation, because the toaster lives at the app root.
- The cost is a change to a shared component. It is mitigated by keeping toasts without an action unchanged, and by the existing toaster tests.

**Acceptance criteria and tests.**
- At 375, 768 and 1440, with an agent toast present, `elementFromPoint` at Undo returns Undo.
- Undo is the only primary button.
- Targets are at least 44px on coarse pointers.
- The toast is at most 2 lines at 375 with a 60-character name.
- A component test of the toaster: action rendering and ordering, and toasts without an action unchanged.
- One live browser check with a real agent toast.
