# K7: Compact, priority-ordered, width-capped tables

**Decision: C (Convention), with Shares shown from `@md` (grafted from A).**
- Both tables use `Table compact className="table-fixed"`.
- Contacts and the Cap table list are wrapped in `max-w-5xl`, left-aligned.
- Cap table columns:
  - Name takes the remainder (no percentage widths).
  - Kind is `w-28`, shown from `@lg`.
  - Shares is `w-20`, shown from `@md`.
  - Ownership is `w-20`, always shown.
  - Email is `w-56`, shown only from `@3xl`, with the email as a muted second line under the name below `@3xl`.
- Contacts keeps Email from `@md` and Organization from `@lg`.

| Judge | A | B | C | Winner |
|-------|---|---|---|--------|
| Usability (lead) | 4 | 4 | 5 | C |
| Visual craft (lead) | 3 | 4 | 5 | C |
| Engineering (lead) | 5 | 2 | 4 | A |
| MUSE Wonder | - | - | - | C |
| Gemini Argon | - | - | - | C |

**Defense.**
- C fixes density and priority on both tables using the existing `compact` prop, with no new API (B's `priority` prop would be a speculative abstraction).
- C applies one density everywhere, where A changes only Contacts.
- The `@md` graft keeps Shares from depending on a 12px margin.

**Acceptance criteria and tests.**
- At 1280 with the Carta panel open: Shares is visible, Email is hidden, and the Name cell is at least 240px wide.
- At 1920 the Contacts table is at most 1024px wide.
- A single-line row is at most 40px tall.
- Checked by browser measurement, and covered by existing tests updated honestly.
