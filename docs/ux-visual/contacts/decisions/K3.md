# K3: Clickable rows through `TableRow onOpen`

**Decision: C (Convention), with B's row focus outline grafted in (no overlay).** Add an optional `onOpen` prop to the ui-web `TableRow`. With it set, the row gets:
- `cursor-pointer`;
- a click handler that ignores clicks landing on another control (`closest("button,a,input,select,textarea")` without `data-row-open`), and clicks made while text is selected;
- `has-[:focus-visible]:` row tint and outline.

The name stays the single tab stop: a `<button data-row-open>` with no onClick of its own, so Enter bubbles to the row. It gets a 2px ring on focus. Carta-only rows on Cap table stay inert.

| Judge | A | B | C | Winner |
|-------|---|---|---|--------|
| Usability (lead) | 4 | 4 | 5 | C |
| Visual craft (lead) | 4 | 4 | 4 | tie |
| Engineering (lead) | 4 | 3 | 5 | C |
| MUSE Wonder | - | - | - | C |
| Gemini Argon | - | - | - | C |

**Defense.**
- C puts the pattern in the design system once. A would be a third hand-written copy, after finance and data room.
- C keeps text selection, which B's overlay breaks.
- C has one tab stop per row, and keeps the nested Cap table buttons safe.

**Acceptance criteria and tests.**
- Clicks on the name, email cell, kind cell and padding open the contact on both pages.
- A click on a nested button does not open it.
- Enter opens exactly once.
- The cursor is a pointer only on rows that have a contact.
- A ring shows on focus.
- A story: "Clickable rows".
