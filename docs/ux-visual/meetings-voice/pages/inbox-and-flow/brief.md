# Brief: inbox-and-flow

Static mockups (no real product yet) of planned features for Rakazo, a monochrome multi-surface workspace app (web, desktop, iOS) with minimal copy and progressive disclosure. Invented sample data. The pill row and page heading above each frame are mockup chrome, not product UI; judge only what is inside the window frame.

Screens attached, in order:
1. Inbox with three meeting to-dos (from Granola meeting notes) above a "Connect Gmail" card, light.
2. Inbox, AI-data consent off: consent card plus Connect Gmail card, light.
3. Inbox with mail connected: To do card above the mail list, dark.
4. Settings, Voice, Wispr Flow connected (transcribe-only provider row), dark.
5. Settings, Voice, Wispr Flow key rejected, light.
6. Voice call card, daily transcription limit reached, light.
7. AI data sharing with a per-recipient switch list, Wispr Flow switched off, light.
8. Wispr Flow agent answering a question with two meeting citation chips, light.

Journeys these screens serve: a meeting-only founder finds follow-up to-dos in the Inbox; a user connects Flow as a transcription provider and later hits a daily cap mid-call; a user asks one meeting agent about meetings from two sources.

For each screen: name the real usability or visual problems (severity P0 to P3), the norm broken, and what is excellent. Say specifically what a first-time user cannot tell from the screen alone.
