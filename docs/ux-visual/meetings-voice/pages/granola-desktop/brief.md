# Second-opinion brief: Granola desktop screens (static mockup, not shipped)

Product: Rakazo, a monochrome web and Electron app where AI "bots" (agents) work for a founder. Ink-on-white UI, one orange identity color for bots only, minimal copy, progressive disclosure. Every visible word is treated as UI and must earn its place.

Feature: Granola meeting sync. A founder pastes a Granola API key (Business plan only) on the Granola integration page. Meetings sync in the background, the "Granola agent" answers questions about them with citation chips, meeting commitments become Inbox to-dos, and the connecting user can delete a stored meeting from the citation popover. Disconnect has no confirmation; it stops the sync, removes the key and keeps all stored meetings.

Screens attached (all frames are drawn at 1440 px wide unless the file name starts with 375). The state pills and the screen title above each frame belong to the mockup, not to the product.
- 1440-light-integrations-detail: Granola detail page before connecting.
- 1440-light-api-key-reconnect: key was revoked; status line, rejection line, editable field.
- 1440-light-api-key-connected: connected card.
- 1440-light-agent-inject: agent answer with tool chips and a citation chip.
- 1440-light-citation-open: popover opened from the citation chip.
- 1440-light-citation-confirm: delete confirmation.
- 1440-light-disconnect-after-full: three frames after Disconnect (card, agent chat, Inbox).
- 375-light-api-key-empty: same card at phone width.

Judge each state as a first-time user and as a senior designer: can the user take the next step, is anything misleading, is the hierarchy right, is any copy unnecessary, are states complete, is it accessible. Do not comment on the mockup scaffolding (pills, titles, small window height). Cite the screenshot file name and the exact element.
