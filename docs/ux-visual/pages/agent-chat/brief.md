# Brief: agent chat surfaces

App: Praci, an AI chief-of-staff for startup founders. Bots (agents) run the founder's inbox, cash, cap table and investor documents. This is a MOCK demo; every name and number is invented.

Page: the chat thread of a single agent (header with agent name and a "Computer and routines" button, message thread, composer with attach, mic and send). Left sidebar lists agents.

Persona: a startup founder (Maya), busy, knows what Mercury (her bank) and Carta (cap table) are, does not know "MCP", tool names or approval mechanics. She wants an answer or a done task, and she must never move money by accident.

States shown in the screenshots:
- Mercury agent: first open (empty thread), a read answer, a payment request and its approval card (pending, allowed once, denied).
- Carta agent: first open.
- Header "Computer" side panel open.
- Composer with a long message and emoji.

Viewports: 1440x900 (desktop), 768x1024 (tablet), 375x812 (phone).

Judge against excellent chat and approval-UI norms: hierarchy, weight of the Allow/Deny buttons, whether the action and amount are clear, readable answered states, density, spacing, alignment, touch targets, and layout at each viewport. Name the norm each problem violates.
