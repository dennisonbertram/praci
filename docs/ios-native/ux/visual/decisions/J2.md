# J2: Inbox prominent action and one control set across sizes

## Problem
PH-Inbox tints Compose and has no route to the Inbox agent or to Cleanup. Sheet, Split and the message view tint "Ask Inbox agent". Split also carries Finance leftovers (Hide amounts, Important only). PG-A-Cleanup draws More as a fourth icon in the actions group, which breaks the three-icon rule, and DS-03 and PG-A-Rules disagree on whether More or the prominent button is last.
Issues: RED-R1-7, RED-R1-8, F-duo-R1-002, F-inbox-computer-R1-001, F-inbox-computer-R1-004, F-inbox-computer-007, STORY-064-R1-3, F-duo-003, F-duo-004, F-duo-012, V-inbox-R1-2, V-inbox-R1-5, V-inbox-R1-15.
Evidence (screenshots read): r1/Sheet.png, Split.png, PH-Inbox.png, Inner.png, PG-A-InboxMessage.png, PG-A-Cleanup.png.
Acceptance (derived, since problems.md lists none for K6): one prominent action, the same on every inbox board; the same control set at every size; the standard iPhone reaches the Inbox agent and Cleanup; at most three glass groups plus the prominent button; every icon has an accessible name.

## Options considered
Weighted score = criteria x3, simplicity x2, consistency x2, usability x2, visual x2, effort x1 (max 60).

| Option | Idea | Usability | Visual craft | Engineering | External (Muse / Gemini) |
|--------|------|-----------|--------------|-------------|--------------------------|
| A Minimal | Ask Inbox agent prominent everywhere; strip Search, Filter, Compose, More(Cleanup) | 51 | 54 | 56 | 49 / 60 |
| B Restructure | Prominent changes per view (Ask, then Reply with prefill); Compose moved into More | 45 | 49 | 42 | 56 / 44 |
| C Apple Mail convention | Compose prominent, Reply prominent; Search becomes "Search or ask" | 32 | 33 | 33 | 34 / 30 |

Totals (three lenses + two external): A 270, B 236, C 162. A wins by 34.

## Decision
Option A, with the following exact rules.

- Prominent action: Ask Inbox agent (chat-bubble icon, ink fill), on the Inbox list at every size and on the message view. Compose and Reply are plain glass.
- Strip order, top to bottom on Duo outer and inner: Island, time, Back; actions group [Search, Filter, Compose]; spacer; More; prominent Ask last. On the standard iPhone the same items run left to right: Back, spacer, [Search, Filter, Compose], More, Ask. That is three glass groups (Back, actions, More) plus the prominent button.
- More holds Cleanup (list icon, title "Cleanup") and opens PG-A-Cleanup. More is its own capsule, never an icon inside the actions group.
- Message view: Back; [Archive, Reply]; spacer; Ask Inbox agent. No More there, because it would hold nothing. Reply is a manual reply. Ask opens the Inbox agent thread with the message attached.
- Wide inner layouts (Split): search is the header field, so the strip is [Filter, Compose], More, Ask. "Important only" moves into the Filter popover. "Hide amounts" is removed (Finance only).
- Inner: Cleanup is added to the Agent actions menu, so no fourth glass group is added.

## Why this is the best
- Against B: moving Compose into More hides the manual path for the most common mail verb, and the prominent button changing meaning between list and message makes the strip move under the thumb. The prefill hand-off is a new contract with no board or issue behind it.
- Against C: it makes the agent a side effect of a search field and removes the only labelled route to the product's main feature. It contradicts every board the other groups already drew.
- Norms met: one tinted action per view, at most three glass groups, icons with accessible names, one control set for all sizes, no Finance controls on mail.
- Cost and what it rules out: the loudest button is the agent, not Compose. A person who only wants to write a mail uses the plain Compose icon, one tap away. The list More menu has one item for now; it exists so Cleanup has a stable home.

## External judges and rebuttal
Muse chose B (it scored the prominent-per-view idea higher, and grafted Compose back onto wide layouts). Gemini chose A. The Muse vote is rebutted above: A already keeps Compose visible on every size, which is what Muse's own graft asks for, and B's per-view prominent change adds a hand-off contract nobody has specified. Gemini's graft (make Reply hand off to the agent with a prefill) is not adopted: Ask and Reply would then do the same thing. Ask with the message attached covers the agent path; Reply stays manual.
