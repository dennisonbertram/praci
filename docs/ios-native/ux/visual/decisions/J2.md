# J2 (round 2, cluster C4): Compose, Send in every frame and one close sheet

Note: this file replaces the round 1 J2 write-up (Inbox prominent action), which used the same label for a different cluster.

## Problem
In PG-A-Compose frames 4 to 7 (Edit draft, Cc suggestions, Invalid address, Discard prompt) the Send arrow is replaced by a "Done" capsule. A draft reopened from Drafts has no Send, and "Done" does not say whether it saves, closes or sends (V-inbox-R2-1). Done stays enabled on an invalid address (STORY-047-R2-3). Two close-with-edits sheets disagree: "Discard changes / Keep editing" and "Save draft / Discard draft / Cancel" (V-inbox-R2-12, RED-R2-5).
Evidence read: r2/PG-A-Compose.png, board source, flow/journeys/STORY-047.md, flow/redundancy.md.
Acceptance (derived, problems.md lists none): Send in every compose frame; no unexplained Done; one close sheet; Send dimmed for no recipient or invalid address; the agent-draft journey stays at 3 to 6 actions with no dead end.

## Decision
Option A, with one graft from C: X on an unchanged draft closes with no sheet (the sheet appears only when the text differs from what was last saved). The sheet is the same in every frame: "Save draft", "Discard" (red), "Keep editing". Edit draft opened from a thread card: Save draft stores the edit on the card; Discard returns the card to the agent's version. Send sends the edited draft immediately.

Done is removed everywhere, so it never needs a dim state. Send dims (opacity 0.35, aria-disabled) with no recipient or with any invalid address; the inline "Not a valid address" text already gives the reason.

## Why this is the best
- Against B: it removes the sheet that RED-R2-5 asked to unify, needs server autosave and a toast state on three return boards, and hides Discard.
- Against C: native confirmationDialog always shows a cancel button and VoiceOver needs it, so a two-action sheet cannot ship as drawn; a labelled "Keep editing" is also easier to hit on the 466 pt strip. Both external judges said the same.
- Journey: edit then Send is 3 actions (Edit, change, Send), one fewer than Done then Send on the card. Reopened drafts can be sent. No dead end.
- Norms: one tinted prominent action per view, Send position constant across frames.
- Costs: Send from the edit view skips the card's "Needs approval" step; pressing Send is the explicit approval of the exact text shown.
- External judges (Muse, Gemini) both chose A. No rebuttal needed. Muse's graft (scrim tap also keeps editing) is native default behavior and needs no board change.

## Implementation plan (SwiftUI)
Toolbar/side-strip Send button always present; disabled state = recipients empty or any invalid. One `confirmationDialog` with Save draft, Discard (role: destructive), Keep editing (role: cancel), shown only when the dirty flag is set.

## Test plan
Board check: each frame of PG-A-Compose has a Send button, none has Done; frame 6 Send dimmed; frames 7 and 8 sheets identical. Later UI test: invalid address disables Send; unchanged close shows no sheet.
