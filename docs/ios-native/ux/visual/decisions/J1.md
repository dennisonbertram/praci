# J1: Model-provider consent (round 2)

## Problem
Round 1 chose "Connect is consent" (one footer line under Connect, no first-send sheet). The thread walker still rates the missing first-use frame high (F-thread-007, V-thread-R2-12) because no board draws the thread after sharing is off or a way to allow it later (F-thread-R1-004, F-thread-R2-009). Also open: Privacy details is a 17 pt text target (V-thread-R2-13), and declining the Inbox agent leaves no frame (V-iphone-R2-13).
Acceptance: one named consent moment; a drawn declined state on thread, Home and Inbox; allow-later in at most one tap with the disclosure visible; Privacy details at 44 pt; one tinted prominent action per view.

## Options considered
Weighted score out of 60 per lens (Usability / Visual / Engineering). Criterion scores in order: acceptance, simplicity, consistency, usability, visual, effort.

External judges: Muse Wonder picked B (A 3/5/4/2/4/5, B 5/4/4/5/4/3, C 4/2/3/4/3/2). Gemini 4 Argon picked C (A 4/4/4/2/4/5, B 5/2/2/4/3/3, C 5/4/5/5/5/4). Raw output in proposals/J1/external-judges.json.

## Decision
Winner: C. Specified in the edit list below.
Grafts: Gemini's graft (Settings off-state line, from A) is kept. Muse's graft (footer as advance notice) is already part of C.

## Why this is the best
- Against A: allow-later takes four taps across three screens and the user flips a switch with no disclosure beside it.
- Against B: it re-adds the gate STORY-019 measured as extra taps; the first reply waits on a second modal after the user already pressed Connect next to a disclosure.
- Norms: one tinted action per view (Turn on, or Allow); disclosure at the action; solid card, no extra glass; the card reuses the no-model card shape on Home and the "Changes to mail are off" card on Inbox, so it adds no new component.
- Costs: more frames to draw; sharing state needs one consent record read by Thread, Home and Inbox.

## Rebuttal to external judges
Muse picked B and says C repeats the card on Home and Inbox where there is no send intent, creating clutter and competing actions. Rebuttal: on Home the card takes the slot the no-model card already uses, so nothing is added to a view that already has a one-card CTA; on Inbox it appears only after the user chose Not now, and replaces the "Consent needed" state rather than adding to it. Each view still has exactly one prominent action. Muse's strongest point, that B gives an explicit moment at first send, is met by the Connect footer, which names Model A beside a button labeled Connect. Muse also scored C's effort 2; the work is mostly frame drawing, and the SwiftUI side is one Toggle bound to the consent record and one card view.
