# J1: First-run model connection and AI data consent

## Problem
First run has two gates: Connect a model, then "Share data with Model A?" on the first send (RED-R1-4, STORY-019-R1-3). The after-connect card offers "Create a bot" although Chief exists (V-home-R1-3, STORY-019-R1-1). The Connect sheet shows one unlabeled key field for all providers, uses letter tiles that duplicate integration-agent avatars, and gives no default (V-home-R1-4/5, STORY-019-R1-2). Missing drawings: wrong key (R1-5), no-model Home on iPhone (R1-6), empty first thread (R1-4), no-model Not sent (F-thread-R1-006), consequence of declining or turning sharing off (V-thread-R1-14/15, F-thread-R1-004), "+" in no-model panels (R1-9), end of life of the connected card (R1-7), Chief row dead end (V-home-R1-6).
Acceptance: one consent moment per provider, naming the provider; after-connect action messages Chief; field and label match the provider; the four missing states drawn.
Evidence: shots r1/PG-A-HomeNoModel.png, PG-B-Consent.png, PH-Home.png, PG-A-ThreadStates.png.

## Options considered
Weighted score out of 60 (criteria x3, simplicity, consistency, usability, visual x2, effort x1), per lens: Usability / Visual / Engineering.
| Option | Idea | U / V / E |
|--------|------|-----------|
| A Minimal | Keep both gates, relabel and add states | 34 / 38 / 43 |
| B Restructure | Full-screen setup page with Model, Speech, Memory switches | 30 / 33 / 32 |
| C Convention | Connect is consent via footer under button; just-in-time Speech and Memory prompts | 54 / 57 / 55 |
External judges (same criteria): Muse Wonder scored A 3/3/3/2/3/5, B 2/2/3/3/3/2, C 4/5/4/5/4/3 and picked C; Gemini 4 Argon scored C 5 on everything except effort 4 and picked C. Both rank C first, A second on effort, B last.

## Decision
Winner: C, with no grafts from external judges (see rebuttal). Grafts from B and A that are kept: the "Privacy details" link (A and B both carry it) and a consequence line in Settings. Full spec is in the per-board edit list returned with this decision.

## Why this is the best
- Against A: A keeps the second sheet, so the first reply still waits on a decision the user made by connecting. It fails the "one consent moment" criterion.
- Against B: B asks about Speech and Memory before the user has seen either, adds a screen, and needs a second Duo layout.
- Norms: one tinted action per view (Connect, Message Chief); disclosure next to the action it governs; permission asked when the capability is first used; minimal copy (one footer line, one Settings footer line).
- Costs: consent now depends on the footer text being read next to the Connect button, so the footer must always name the provider (real provider name comes from the adapter, not hard-coded). Hiding "+" until connected moves layout once on connect.

## Rebuttal to external judges
Muse proposed a default-off consent switch on the Connect sheet. Rejected: it is a second decision on the same screen, so the user pays a tap for a choice the Connect button already expresses; the disclosure sits directly above a button labeled Connect, which is explicit permission. Gemini had no graft. Both judges chose C, so no disagreement to rebut.
