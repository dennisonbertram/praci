# J5: Where permissions and preferences live in Settings

## Problem
"Allowed without asking" (tools an agent may run without a prompt) is the last row of the AI data sharing page, so a person managing agent permissions has to look under a page about where data is sent. Language, Appearance and Hide amounts are only in Account (V-account-R3-9, RED-R3-19). Server has a row in Settings and another in Account (RED-R3-1, V-account-R3-2). The PH-Pages Settings frame does not match PG-B-Settings: it has "Archived agents", no Server row, and the profile and Account sit below the list (F-finance-settings-R3-003 is the same drift in the rule card).
Acceptance (problems.md C9): "Allowed without asking" is a top-level Settings row; Language, Appearance, Hide amounts in Settings; Server appears once; Account keeps identity.
Evidence: screenshots of PG-B-Settings, PG-B-Account, PG-B-Server and PH-Pages (round 3).

## Options considered
Weighted scores, max 60 (criterion 1 x3, criteria 2 to 6 as in the rubric). Lens scores are mine; external scores come from external-judges.json.
| Option | Idea | Usability | Visual | Build risk | Muse Wonder | Gemini 4 Argon | Total (3 lenses) |
|---|---|---|---|---|---|---|---|
| A Minimal | Add permissions row, drop Server from Account; preferences stay in Account | 39 | 39 | 47 | 35 | 35 | 125 |
| B Restructure | New "Agent permissions" and "Preferences" pages; Account identity only | 44 | 44 | 48 | 44 | 41 | 136 |
| C Convention | Apple Settings: one flat list, inline switch and menu, no new pages | 57 | 53 | 51 | 51 | 57 | 161 |
A fails criterion 1 (Language, Appearance and Hide amounts stay in Account) and is disqualified. Both external judges picked C.

## Decision
Option C, the iOS Settings pattern: one grouped list where a switch or short choice is a row in the list and a detail page exists only for a list to manage.

Settings root, top to bottom (the same on PG-B-Settings and PH-Pages):
1. Profile row "Sam Rivera / Account".
2. Models, Voice, Integrations.
3. AI data sharing, Allowed without asking (count).
4. Hide amounts (switch), Appearance (value, native menu), Language (value, opens iOS Settings for Praci).
5. Server (value), Archived bots.
Account keeps only name, email, Change password, Sign out, Delete account.

Grafts: none accepted. Muse suggested a "Preferences" section header from B. Declined: it adds a visible word that only labels three self-explanatory rows, and Apple Settings separates groups by spacing alone. The README asks to start UX work by asking what can be removed.

## Why this is the best
- Against A: leaves the main finding open; a person looking for Appearance still finds nothing in Settings.
- Against B: two new pages for four small items, an extra tap for the two urgent tasks (mask amounts before a screen share, switch to dark), and a Preferences page with three rows on a 466 pt strip. Both judges flagged "Preferences inside Settings" as redundant.
- Norms: one place per setting, one tap for switches, progressive disclosure (the permission list opens only from its row), native controls. Costs: the root has 10 rows plus profile and scrolls on the 466 pt strip; Language leaves the app (an in-app picker is a pushed list if the product prefers it).
- External judges agreed with C, so no rebuttal is needed.

## Implementation plan
Boards only. SwiftUI later: List with Sections; Toggle bound to the same @AppStorage flag as the Finance eye; Picker with .menu style for Appearance; Button calling UIApplication.open(openSettingsURLString) for Language; NavigationLink with count for Allowed without asking.
