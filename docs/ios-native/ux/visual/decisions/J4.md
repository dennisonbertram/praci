# J4: Home order of Inbox, Pages and Personnel

## Problem
On PH-Home the Inbox row ("3 need reply") is the first row of the PAGES card, which starts below Personnel and is cut by the fold at y=852. Split lists Pages before Personnel while PH-Home, PG-A-Home and Main list Personnel before Pages, so the same Home has two orders. Findings covered: V-iphone-R2-6, RED-R2-1, F-thread-016, F-thread-019. Recency sort of Personnel is decided elsewhere (fix group 1) and is not changed here.

Acceptance criteria used for scoring:
1. Inbox with its count is visible without scrolling on PH-Home (393x852) and on the Duo outer display (466x678).
2. Home, Main and Split use one section order.
3. Personnel stays visible (Chief and at least three agents) so chat remains the primary path.
4. Inbox appears once, not as two entries.

## Options considered
Weighted score = 3 x criteria + 2 x (simplicity + consistency + usability + visual) + effort. Maximum 60.

| Option | Idea | Usability / Visual / Engineering lens | Muse Wonder | Gemini 4 Argon |
|--------|------|----------------------------------------|-------------|----------------|
| A Minimal | Pages above Personnel everywhere | 45 / 47 / 54 (total 146) | 49 | 49 |
| B Restructure | Pages become a chip strip above Personnel | 29 / 33 / 35 (total 97) | 32 | 32 |
| C Pinned row | Inbox pinned under Activity, order Activity, Inbox, Personnel, Pages | 53 / 51 / 51 (total 155) | 55 | 58 |

External judges are in `proposals/J4/external-judges.json`. Both picked C with no graft.

## Decision
Option C, the pinned smart-list row (Things Inbox, Apple Mail Inboxes, Linear Inbox). The order on every Home surface is Activity, Inbox, Personnel, Pages. Inbox leaves the Pages list. No section label is added for the Inbox row.

Graft from A: no new component or style. The Inbox row copies the existing Pages row recipe exactly, so the only change is where it sits.

## Why this is the best
- Against A: A puts a static 264 px list of six pages above Personnel. On the Duo outer display Pages end near y=560 and only Chief fits, so the most used list (agents, recency sorted) is pushed down to fix one row. C costs Personnel one 44 px row.
- Against B: chips drop the subtitles that carry information ("6 mo runway", "2 deadlines", Online), turn "3 need reply" into a bare "3", need a custom wrapping layout, and are not a native iOS list.
- Norms satisfied: one order everywhere, one Inbox entry, solid content with no extra glass, no added copy, same row recipe as Pages, native `List` sections.
- Costs: Inbox is no longer listed among the other pages. It still opens the same screen and looks like a Pages row, so this is small.
