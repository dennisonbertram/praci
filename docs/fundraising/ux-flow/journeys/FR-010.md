## Take-away Pass

**Investors page (mock-investors.png).**
- Action items "October update" row and the Updates list "October update" row show the same draft twice, with the same Draft tag and Review button. Keep the Action items row (it is the thing that needs attention) and show a draft in Updates only as a plain row without a second Review button, or hide drafts from Updates while an Action item exists. Suspected: removing it loses nothing, since Updates still shows history.
- The sidebar dot on Investors (mockup line 149, aria-label "2 action items") is the only unprompted signal. The story's step 1 says the plan is silent on push or desktop notification. Measured: nothing else tells Maya the draft exists on the 1st. Do not add chrome; the dot is enough if it also reaches the mobile push the README already promises for the agent chat.
- The Updates card header carries Monthly / Quarterly / Off plus New update. Cadence is a setting touched once. Suspected: move it behind a small overflow ("Reminder: Monthly") so the header has one action, New update. This also shortens the card, which is already below the fold in the screenshot (Updates starts at roughly y=800 in a 1000px frame).
- "Message the board" sits in the Contacts card header (mock-investors.png, top right of Contacts). It is an update action living in a contacts card. See FR-017 below.

**Update editor (mock-editor.png).**
- Title (h1), Period and Subject: three fields for one fact. Remove the Period field from the editor (keep it as row data the agent fills). Keep one editable line, the Subject, which also serves as the title. Measured saving: two fields.
- Audience chips (Investors / Board) on an existing draft: the routine fixes the audience, and "Message the board" and New update choose it at creation. Switching audience on a drafted body is an edge case the story lists as unspecified. Suspected: show audience as read-only text in the To line ("Investors: Elena Ruiz, Tom Okafor, Sam Lind, Priya Raman"), not as a control.
- To line: names are shown, but the plan has no way to deselect (STORY-203 says "Uncheck Priya" while the mockup shows plain text, not checkboxes). Not a take-away; a gap. Do not add a recipient picker; a per-name remove (x) is enough.
- Draft with agent: on a draft the routine already wrote, this button has nothing to do. Hide it when the body is non-empty (and name it "Redraft" only then, if at all). Measured: it is the second of three equal-weight buttons.
- Share to portal versus Send: two buttons that both share. README says Send adds the portal link in the footer and also shares (slice 6). Remove the standalone Share to portal; make portal sharing a default that Send performs. The only use left for a share-only action is "Connect Gmail to send" mode, which the plan keeps; keep that as the single fallback, not a permanent button.
- Footer hint "TBD stays TBD until you fill it. Send adds the portal link in the footer." is persistent explainer text. First half belongs inline: highlight the TBD token itself and say nothing. Second half is a fact about Send; move it to a one-line preview under the body or drop it.
- "Bcc from your Gmail": small but states a mechanism. A new founder may not know why recipients are hidden. Suspected: say "Each investor gets their own copy" (not verified against how Bcc is rendered to them).
- Draft status tag, top right: the only state indicator. Keep.

**One primary action.** Send is the only dark button on the editor and the dot on the page: correct. Draft with agent and Share to portal are the same visual weight as each other; after the changes above they disappear in the normal case.

## The Simpler Version

1. Nov 1, 09:00 the routine saves the draft. The Investors sidebar dot lights and the mobile/desktop push says "October update ready" (measured: the plan names the dot only).
2. Maya opens Investors. The top Action item reads "October update, ready to review" with Review.
3. The editor opens: one Subject line, the To line, the body. Remaining TBD tokens are highlighted.
4. She types over "Customers: TBD". The draft autosaves (state shown only as "Saved" when it changes).
5. She clicks Send. It goes Bcc from her Gmail, shares to the portal and returns her to Investors with September, October both Sent. If any TBD remains, Send pauses once: "1 TBD left. Send anyway?" (this is the one confirmation that guards a real mistake).

That is the same five steps with fewer fields and no second path to the same draft. Step economy is not the problem here. Field and control count is.

## Proposed Plan Changes

README "Pages > Update editor":
1. Drop Period and Audience as editable fields; keep both as row data. Title and Subject become one field. Edit the mockup editor accordingly.
2. Remove the standalone Share to portal button. Send shares; "Connect Gmail to send" mode keeps a share-only action.
3. Hide Draft with agent when the body is non-empty; highlight TBD in the body; delete the footer hint line or reduce it to one sentence.
4. State autosave (no Save button) and what Send does on leftover TBD (single prompt). These resolve two listed gaps (no Save, no TBD guard).
5. State that Send returns to Investors.

README "Pages > Investors":
6. Show a draft update only once: as the Action item. The Updates list rows are history (Sent) plus New update. Remove the second Review button.
7. Move the cadence control (Monthly, Quarterly, Off) out of the Updates header into an overflow or the agent's routine settings. Updates header keeps only New update.

README slice 5 / notification:
8. Decide the notification: dot only on web, plus the existing mobile push to the agent chat (README slice 5 Mobile line). Say so in one line to close the plan gap.

## FR-017 (board) in brief

Verdict: acceptable, with one redundancy. "Message the board" (Contacts card header) is a shortcut to New update with Audience Board and board recipients; the story names it a duplicate of New update then Audience switch. Measured: three ways to start a board note (button, Audience chip, chat). Proposed:
- Remove the Audience chip on a new update (the shortcut and New update each fix the audience), or keep the chip and drop the button. Pick one canonical route. Recommended: keep "Message the board" on the Board tab only (it sits where board members are visible), and make New update always mean investors.
- The board routine is "the same row with audience board, off by default" (README "Routines") but the cadence control is investor-only in the mockup. Do not add a second control. Fold it in: one "Reminders" overflow with two rows, Investors (Monthly) and Board (Off). This reuses proposal 7.
- A person who is both investor and board is a single `kind` (story edge case): plan silent. Keep it out of scope; note in plan as a known limit.

## Clarity Issues

- One concept, three names: the item is called "update" (button New update, Updates card), "note" ("Q3 board note", mockup line 213), and "Draft" is both a status tag and a skill action ("Draft with agent"). Choose "update" for investor and board messages; rename "Q3 board note" to "Q3 board update" in the mockup.
- "Share to portal" assumes the founder knows what the portal is. The portal is introduced only in Contacts (a Portal column with Active / Link sent). Suspected confusion for a first-time user; removing the button (change 2) removes the term from this screen.
- "TBD" is clear to founders; "TL;DR", "Lowlights" are agent section names and fine, but they are editable text, not UI.
- "Bcc from your Gmail" uses jargon (Bcc); see take-away pass for a plainer line.
- The sidebar dot has an aria-label ("2 action items") but no visible count; the mockup dot cannot tell Maya whether the update or the audit is the item. Acceptable as is; the Action items list answers it on arrival.
- Status words: Action items shows "Draft" for this item while an audit shows "Draft ready" (mock-investors.png). Same state, two words. Use "Ready to review" for both (suspected small inconsistency, measured in screenshot labels).
