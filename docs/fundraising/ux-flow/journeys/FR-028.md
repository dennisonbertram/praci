## Is the Jan-Mar routine needed? (the question asked)

Measured facts:
- Mail auto-filing already runs on incoming mail (`mail-attachment-filing.ts`, README line 92), but only for attachments from the last 2 days (STORY-401 step 1, `AUTO_FILE_MAX_AGE_MS`).
- The routine is weekly and only Jan-Mar. It uses a 120-day `mail_grep` window (README Audits step 1).
- That design causes three of the four journeys' problems: 409 (founder impatient, waits up to 6 days), 406 (October request never found, sidebar silent), and R16/PG-57 (sync and agent both file the same PDF, because the routine is late and the sync is early).

Suspected (needs a code check): the sync can run a cheap match (subject/sender/body words "audit", "confirmation", "DocuSign") on each new message and enqueue one agent run for that thread, the way it already decides to auto-file. If it can, the routine is unnecessary.

Verdict: a seasonal polling routine is the wrong tool for a rare, email-triggered event. React to the message instead:
- Latency drops from up to 7 days to minutes (fixes 409 without any founder action).
- Off-season requests (406) work with no special case.
- One filer: the same event that auto-files the attachment passes its Data room item id to the agent, so there is no double filing (R16, PG-57).
- No Audit season routine, no season dates, no 120-day window, no "routine UI" gap (STORY-406 and 409 alternates).
- Keep Ask ("check for audit requests") as the fallback for requests that arrive outside Gmail (FR-032), not as the normal way to start.
- Cost to watch: false positives rise because matching runs on all mail, not a weekly grep. That makes Dismiss (404) a real, frequent control, and "dismissed stays dismissed by thread" must be tested (it already is a stated need).

## The Simpler Version

Founder path:
1. Notification: "Audit request from Fenwick Ridge Capital Fund III" sent once, when the draft is ready (not at New), opening Investors.
2. Action items row: click Open draft (Gmail).
3. Compare with the filed PDF, edit, send in Gmail. The row closes by itself when the thread shows the sent reply; "Mark done" stays in the row menu as a fallback.

Agent path (no founder involvement): new message matches, PDF filed once, row upserted, draft saved, notification.

404 Dismiss: row "…" menu, Dismiss. One step. Row hides; same thread never recreates it. A "Dismissed" count is not needed; the Data room item is left alone.
406 off-season: nothing to do; it works like 401.
409 start now: not a journey any more. The founder does nothing; if she wants a re-run she uses Ask.

## Clarity Issues

- "Action items" holds three unrelated kinds (audit, SAFE, update draft) with three different button verbs: Open draft, View, Review. One concept, one verb would help, but this is outside FR-028.
- "Audit request" is the row title while the agent skill and routine are "audit-response" and "Audit season", and the contact tab is "Auditors". A founder sees "audit" for a fund's confirmation of her holdings; many will not call it an audit. Suspected: "Holdings confirmation" matches the email they actually receive. Low priority, check with the real subject lines.
- "Draft ready" (badge) versus the state names New, Draft ready, Done in README Action items: the mockup shows only Draft ready, so the other two states are unseen. Show the New state in the mockup if it stays.
- "as of Dec 31" is clear; "due Mar 15" is clear.

## Verdict

acceptable. The founder-facing journey is already close to ideal (5 steps vs 3). The friction is upstream: a weekly Jan-Mar routine creates the latency, off-season miss, double filing and the "start now" workaround. Replacing it with event-driven intake removes 406 and 409 as journeys.
