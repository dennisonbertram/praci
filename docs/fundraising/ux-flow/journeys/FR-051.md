# FR-051: Six-week $750k pre-seed SAFE round, end to end

Source story: STORY-604 in `docs/fundraising/ux-paths/topics/first-run-and-cross-page.md`. Also considered: STORY-601 (FR-048, brand-new founder) and STORY-608 (FR-055, who to ask about a SAFE deposit). Focus: friction between Investors and Fundraising, and which agent the founder talks to.

Evidence: plan `docs/fundraising/README.md`; mockup `docs/fundraising/mockup.html`; screenshots `ux-flow/screens/mock-investors.png`, `mock-fundraising.png`. "Measured" means read from the plan, mockup or story. "Suspected" means inferred.

Steps the founder cannot avoid and that look right: Start a round, add prospects, move stages (one menu action each), review and Send the update, Close round. Decisions where 90 percent of users pick the same option and a default could carry: SAFE creation route (Mercury if connected), prospect to investor on signing, portal link sent with the update, Ask target.

Brand-new founder (FR-048, story 601): Ideal path is 5 steps and the plan matches it. Friction found: the Empty view has three equal buttons and no hint (Connect Carta, Use a Google Sheet, Edit here); the mockup has no Fundraising empty view. This is documented in the story gaps, so it is only noted here. A founder who wants to raise money first must open Investors, pick a source and type founders before Fundraising feels useful; Fundraising itself does not need a cap table to add a prospect (story step 5), so this is a suspected, small sequencing cost, not a defect.

## Take-away Pass

**Investors page (`mock-investors.png`)**
- Action items: the SAFE row repeats Fundraising's SAFE row. Keep the audit and update items (they have no other home on the page). Remove the SAFE item or make it a one-line mention with no button of its own; the founder works on Fundraising.
- Cap table SAFE rows, "SAFEs shown unconverted", legend "SAFEs at cap 6.7%" and KPI "incl. $450k in SAFEs": four renderings of one concept on one screen. The SAFE rows and the bar are enough; the KPI subtitle can stay because it explains the number. Suspected: the "SAFEs shown unconverted" label can be dropped since each row is already tagged "SAFE" and "x% at cap".
- Header carries three source chips (Carta, Google Sheet, Edit here) plus Add contact plus Ask. After a source is chosen the chips are a setting, not a daily control (suspected). Collapse to the "Carta · as of Sep 30" text with a menu. This is already the subject of other journeys, so only flagged.
- Contacts "Portal" column shows "Send link" per row. Remove the manual action when the contact has just been emailed an update with the link in the footer.

**Fundraising page (`mock-fundraising.png`)**
- Header has three equal-weight-looking buttons: Add prospect, New SAFE (black), Ask (black). Two black buttons compete. The plan says one primary action; here New SAFE and Ask are both dark. Make "Add prospect" the primary while the pipeline is small, and show "New SAFE" only when no prospect row could carry the action (it is the escape hatch, since "Create SAFE" on a Committed row already prefills). Measured for the competing buttons; suspected for which should win.
- Pipeline rows: stage chip tag on the right ("Diligence", "Meeting", "Intro", "Target") repeats the group heading directly above. Remove the chip. Measured.
- Committed rows keep "Create SAFE" after a SAFE exists. Replace with the SAFE's status chip.
- "Close round" sits in the round card header next to the cap text, always visible. Showing it only when funded reaches target or the founder opens the card menu would defer an action used once. Suspected.
- Round card: legend "Funded / Signed / Committed / Target" reads fine; fix the word "Committed" (see Clarity).
- SAFEs table: "Mercury", "here", "cover summary" in the subline is internal vocabulary for the source ("here" means native). Replace with nothing for Mercury-connected rows or one consistent source word.
- Refresh and Hide amounts icons are the same in the header of both pages; fine.

**Ask panel (both pages)**
- One agent for both pages is correct for the founder (README: same agent). The mockup Bots list also shows Carta agent and Finance agent permanently. For a Mercury-and-Gmail founder with no Carta, the Carta agent is noise (mockup shows it though story 604 says no Carta; the plan says it appears only after Carta connects, but the mockup does not show that). Measured.

## The Simpler Version

Assumes the plan changes below.

1. Fundraising > "Start a round": target, cap. Defaults MFN on. (Same as today.)
2. "Add prospect" for each investor: name, check size (email optional). Same as today.
3. Move a prospect to Committed from the row menu.
4. On the Committed row, one button, "Send SAFE". With Mercury connected it opens Mercury's SAFE flow with the contact and amount; without Mercury it opens the native dialog. The founder never chooses between the two. The row now shows the SAFE's status chip instead of the button.
5. Status moves by itself from Mercury (Sent, Signed, Funded; deposit matched). Without Mercury the row chip is the only manual control (Sent, Signed, Funded).
6. When a SAFE is Signed, the prospect becomes an investor automatically (same contact, `kind` changes). It leaves the Pipeline and appears in Contacts > Investors, and in the update recipient list.
7. If a Signed SAFE has no matching deposit, the SAFE row is the only place to see it. The Investors page shows a count line, not an item with a button, or nothing; the sidebar dot is for items the founder must act on.
8. Investors > Updates: Review the drafted update; the draft reads round totals from the round; Send. The portal link goes with the email and every recipient is "Active" or "Link sent" automatically; no per-contact "Send link" is needed for them.
9. Fundraising > Close round when done (confirm only if a SAFE is Signed but not Funded).
10. Later: audit request arrives as an Action item on Investors (unchanged).

Step count from "Committed" to "Funded and on the cap table": 3 founder actions (Send SAFE, sign outside Rakazo, nothing else) versus today's 5 to 7 (choose route, create SAFE, wait for sync, change contact kind, send link, open Investors to check). Estimate, based on story steps 4 to 10 and 16.

## Proposed Plan Changes

Small, mostly removals.

1. **README Fundraising section 2 / slice 9:** a Committed row with a SAFE shows that SAFE's status instead of "Create SAFE". Mockup: remove the stage chip from pipeline rows; remove "Create SAFE" from Harbor and Dana, show their chips.
2. **README slice 10 and 11:** one button for starting a SAFE. When Mercury is connected, "Create SAFE" on the row hands off to Mercury's flow; when not, it opens the native dialog. Keep the header "New SAFE" only as a secondary action (or drop it, since the row action carries the prefill). Mockup: demote the header "New SAFE" to the default button style.
3. **README Data model (`Contact`) and slice 10/11:** a Signed SAFE (or a SAFE with `signedByInvestorAt`) sets the linked contact `kind` to investor. Then pipeline, Investors Contacts and update recipients agree without a user action.
4. **README slice 5 / Investors Contacts:** contacts that receive an update get the portal link in the footer and are marked "Link sent"; keep "Send link" only for contacts who were not in an update.
5. **README slice 2 and slice 9 (agent):** give the Investors agent read of the round, pipeline stage, SAFE rows and the deposit-match state before "Ask" on Fundraising opens it, or have "Ask" on Fundraising open with a suggestion that matches what it can do. For deposit questions, the SAFE row's "Deposit matched / No deposit found" text is the answer; the agent quotes it instead of routing to Finance or Mercury. Drop STORY-608's four-agent route from any founder-facing copy.
6. **README Fundraising section 1 and mockup legend:** one word per concept. Use "Committed" only for the pipeline stage; the Round card says "Signed".
7. **README notifications and Investors Action items:** keep the SAFE-needs-attention item on Fundraising (it is the working page) with the dot on the Fundraising sidebar link; Investors keeps audit and update items.
8. **Mockup fixes (evidence only):** SAFEs header "4 · $700k" should read $600k; Round Target should match the example round.
9. **Mockup sidebar:** show only the agents that exist for the example founder. The plan says the Carta agent appears after Carta connects; the screenshot shows all three at once.

## Clarity Issues

- "Committed": pipeline stage and signed SAFEs (see 6). Also "committed" in the Committed row ("send SAFE") versus the legend.
- "here" in the SAFE subline (`Oct 18 · here · cover summary`) means the SAFE was made in Rakazo. An early founder will read it as a typo. Suspected.
- "Mercury" versus "here": two source names for one concept; rows should say the source in plain words or not at all.
- "No deposit found" with no next step. It tells the founder something is missing but not what to do. Measured: story edge case, rows read-only. The simplest fix is the SAFE row menu: "Mark funded" (copy needs approval under AGENTS.md; reveal only on this state).
- "Awaiting deposit" (Investors chip) versus "No deposit found" (Fundraising row): two phrases for the same state.
- "Pipeline" and "Investors" both list people at different stages; the founder has to know the prospect becomes an investor on a separate page. The automatic kind change (proposal 3) removes this need for explanation.
- "Investors agent" is the only name the founder needs for drafting and asking. The Bots list adds "Carta agent" and "Finance agent" next to it with no hint of which one to use; the story's own gap says no routing text exists. Proposal 5 is the minimum.
- "Fully diluted" and "at cap" assume cap-table vocabulary; both are standard for the audience and already in the plan, so no change proposed.

## Verdict

Acceptable, not minimal. The core path (start round, add prospects, move stages, send update) is short and sensible. The friction is concentrated where the two pages meet: a prospect's SAFE is not linked back to its row, "Create SAFE" and "New SAFE" collide with Mercury's flow, signing does not move the contact to Investors, and the Action item on Investors points the founder to Fundraising for a state that already shows there. Agent choice is mostly a gap in what the Investors agent can read, not an interface problem; one agent on both pages is the right design if it can read the round.
