## Take-away Pass

Fundraising page
- Header "New SAFE" primary button: remove from the header. A SAFE for someone not in the pipeline can be created by adding them as a prospect in Committed, or from a "New SAFE" text action on the SAFEs card. One primary action per heading is better served by Ask staying the only filled button. (Take-away test, one primary action.)
- Round card legend has four items (Funded, Signed, Committed, Target). Keep them, but define Committed once (below). No removal.
- SAFEs card header "4 · $700k" is a third total next to the legend (Funded 450 + Signed 50 + Committed 150). Suspected confusion; R15 already notes it. Show the count only, or drop the dollar figure, since the bar carries amounts.
- SAFE row subtitle "Oct 18 · here · cover summary": "here" is unexplained. Drop it; native rows are the ones with a cover summary link, so the link alone says it.
- Pipeline Committed row: after a SAFE exists the row should not show Create SAFE and should not stay in the pipeline (see Simpler Version).

SAFE dialog (not in a screenshot; planned fields)
- Defer to a "Different terms" disclosure: terms type, cap, discount, MFN. They come from the round. Show investor, amount, date only.
- Pro rata, governing state: defaults, shown in the same disclosure.

Investors page
- Action item "SAFE signed, not funded" and the cap table SAFE row already exist (R9). No change for this journey.

## The Simpler Version

Definition of "Committed" (one): **a prospect stage meaning the investor said yes and no SAFE exists yet.** Its dollar value is the prospect's check size. Everything past that is named by SAFE status: Draft, Sent, Signed, Funded. README's "committed (signed SAFEs)" is replaced by "Signed". The round bar reads Funded, Signed, Committed (not yet in a SAFE), Target. When a SAFE is created, its amount replaces the check size, so the same dollars never count twice.

Canonical place a SAFE is entered: **the SAFE dialog on Fundraising, reached from the Committed row** (also from a text action on the SAFEs card). Not the cap table editor (R2 already says so). When Mercury is connected, the Committed row shows "Send in Mercury" (link out) in place of Create SAFE, because Mercury is the sender (README decision 3). Native Create SAFE is the no-Mercury path only. This removes most double entry. The email-and-amount merge stays as a backstop and is not advertised.

Prospect to investor transition (simplest): **no user action, no new screen.**
- The pipeline lists prospects with no active SAFE. Creating a SAFE (native or Mercury match) moves the person from the pipeline to the SAFEs card. A Canceled SAFE returns them to the pipeline.
- The contact's `kind` becomes investor when the SAFE is Signed. Do not null `stage`, so the history survives; the pipeline simply filters on kind and SAFE.
- No notice. The SAFE row appearing in SAFEs and the Investors cap table row are the feedback.

Journey in the fewest steps:
1. Click Create SAFE on Dana Whitfield. The dialog opens with investor, $100,000, today's date, and the round's terms already filled.
2. Click Save. The cover summary opens (print view with a Print button).
3. Print, fill the YC form outside Rakazo, send it. Back on Fundraising, Dana Whitfield is in SAFEs as Draft and gone from Committed.
Later, mark Sent, Signed, Funded from the row menu (FR-040). On Signed, she appears on Investors as an investor.
That is 3 steps, versus 7 to 8 planned, with no detour to find the row.

## Clarity Issues

- "Committed" has three meanings (README Round; Pipeline stage; mockup legend). Fix by plan change 1.
- "Create SAFE" (row) and "New SAFE" (header) name one action twice. Use "Create SAFE" only; the SAFEs-card action can read "Add SAFE" only if it is kept, but one verb is better (R2 and "one concept, one name").
- "Signed", "Committed", "Funded" mix stage and SAFE status vocabulary in one bar legend. Plan change 1 keeps stage words for the pipeline and status words for SAFEs.
- "here" in "Oct 18 · here · cover summary" is unexplained (measured: mock-fundraising.png, Dana Whitfield row). Source labels elsewhere read "Mercury"; use nothing for native.
- "Raised $1.45M incl. $450k in SAFEs" on Investors, "Funded $450k" on Fundraising, "4 · $700k" in SAFEs: three SAFE totals (PG/R15). The first two agree; the third is all SAFEs including Draft and Signed. Drop it.
- "unconverted" and "at cap" on the Investors cap table assume the founder knows how SAFEs convert; the cap table already has a "SAFEs shown unconverted" label (mock-investors.png), so no change beyond what exists.
- "Governing state" in the dialog assumes legal knowledge; if it is kept, it should default and sit in the disclosure.
