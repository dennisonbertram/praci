## Take-away Pass

### Investors, empty state (`mock-empty.png`)
- Title "Investors" plus three buttons. This is already minimal; nothing to remove. One primary (Connect Carta), correct only if most users have Carta. Suspected: a pre-seed founder like Tomas has no Carta, so the primary action points at the wrong default for the very persona who types by hand.
- Missing, not extra: no way to tell the three apart (PG-14). The fix is not a paragraph (AGENTS.md: no explainer text); shorter, self-explaining labels do the work: "Connect Carta", "Use a Google Sheet", "Type it in".

### Investors, header source control (`mock-investors.png`, mockup `.seg`)
- The control shows three chips (Carta, Google Sheet, Edit here) permanently, plus a separate Refresh icon next to the title and a "Carta · as of Sep 30" meta line. The source is therefore stated twice: the selected chip and the meta text. Take away: the chip row.
- Why: a founder picks a source once. Switching is rare (FR-005 is a "six months later" story). A persistent three-way segmented control spends header space on a rare action and, worse, makes each chip a destructive action (clicking Carta overwrites the table, per slice 3). A control that looks like a harmless tab but replaces data is a trap. Suspected, but the story's own preconditions (steps 1 to 3 of STORY-105) show the click is the trigger.
- Replacement: show only the meta line ("Carta · as of Sep 30" or "Edited by hand · Oct 20") and put "Change source" in the existing per-page menu or the meta line itself. This removes three chips from the header and answers R1 (two refresh controls) by also keeping a single Refresh.
- Header already holds Hide amounts (eye), Refresh, Add contact, Ask, plus the chips: 6 or 7 controls. Removing the chips helps FR-008 (phone) too.

### Investors, cap table section with editor (plan only, no screen)
- Editor columns are name, email, security, shares, amount (five). Candidates to remove or defer: email (needed only to join with Contacts; could be optional or filled by picking an existing Contact), amount (needed only for investors; founders have none, mockup shows "—"). Suspected: show email and amount only for rows whose security is Preferred or SAFE... but SAFE should go (below).
- Remove SAFE from the security list (R2 already proposes it). SAFEs live on Fundraising; this deletes one choice and removes the double-count risk (story step 6).
- Merge Pool and Option into the vocabulary the table already shows. Mockup rows read "Options granted · Option" and "Pool available · Pool", so these are two real, different rows. A founder typing 1,000,000 under Pool needs to know it means unallocated shares. Either one row type "Option pool" with granted and available numbers, or keep both with row labels that explain themselves.
- Summary tiles above the table (Fully diluted, Raised, Option pool, Latest 409A) appear for a native table too. A founders-only table has no Raised and no 409A (PG-18). Hide tiles with nothing to show, rather than "$0" or "—".
- Per-row menu ("...") already exists in the mockup for Carta rows; for native rows the editor needs delete. Reuse the same menu, do not add a second editing mode.

### Source switch confirmation (FR-005)
- "Says so" is the plan's only statement. One decision needed: warning before, not after. A single inline line under the chosen source ("This replaces the 6 rows you typed") before the read starts is enough; a modal is not required. Undo (keep the previous snapshot one version back) is cheaper to explain than any warning and removes the confirm entirely (heuristic 4, "prefer undo over confirm"). The plan has one snapshot row per space and user, so this needs a stored previous version: a small data-model change, flagged below as optional.

## The Simpler Version

Tomas, goal: enter 4 holders and see fully diluted percentages.

1. Open Investors (empty page). Click "Type it in".
2. A table appears with one blank row and the founder's name/email prefilled. Type a name, shares; security defaults to Common. Press Enter or click "Add row" to get the next row. Repeat per holder (investor rows add amount, optionally picking an existing Contact so email is not retyped).
3. Rows save as the user leaves each field (no Save button, no unsaved-changes prompt). Percentages and the ownership bar update live.
4. Done. The meta line reads "Typed in · updated just now". Reload shows the same table; the cell is editable in place, so there is no separate "edit mode".

Switching later (FR-005, FR-009):
1. Open the header menu, choose "Connect Carta" (or "Use a Google Sheet"). The inline line says what will be replaced. Carta signs in, reads, done. The previous typed table stays one version back, with an "Undo" next to "Reading Carta…" result.

That is 4 user actions for the main journey versus 9 planned steps. The difference is mostly removing the explicit Save, the header check, and the reload.

## Proposed Plan Changes

1. README Pages > Investors header: replace the three-chip source control with a one-line meta ("<Source> · as of <date>") and a "Change source" entry in the existing menu. Update `mockup.html` line 170 (`.seg`) and the screenshot. Fixes R1 and the trap where a chip click overwrites data (PG-19).
2. README slice 3: make the editor an always-editable table (autosave on blur, one blank row at the bottom) instead of a mode with Save; defaults: security Common, company name from the space, as-of = last edit. Closes PG-15 (unsaved changes, required fields, schema's `companyName`/`asOf`) and the "Edit here toggles back into the editor" step.
3. README slice 3 security list: drop SAFE (SAFEs only on Fundraising, R2), and say one pool row type with "granted" and "available" or label Pool as "Option pool (unallocated)". Closes the double-count in story step 6.
4. README slice 3 and 4 behavior: state the rule for which source wins when Carta is connected (PG-20). Suggested: the last chosen source wins and a connected Carta stops auto-syncing until chosen again; today the plan says both. Without this FR-009 has no coherent answer and the "source silently flips" step cannot be tested.
5. README slice 3: when switching source, keep the previous snapshot one step back with Undo (inline, after the read), instead of a confirm dialog. Optional: if too heavy, show a single inline sentence before the read.
6. README slice 2/3 empty page: rename "Edit here" to "Type it in" (or "Enter by hand") on the empty page and in the menu; edit `mockup.html` line 328. No helper paragraph.
7. README slice 3: holders typed with an email should link to an existing Contact or create one (PG-16, R14), so the same investor is entered once. Use the Contacts table already on the page.
8. Empty primary button: consider making the first action neutral (all three secondary) or choose by a cheap signal (Carta connected in Integrations) rather than always Carta. Suspected only; keep if Carta users are the target.

## Clarity Issues

- "Edit here" (empty page, header chip, plan, story) names a place, not an action; it is also the only source whose name is not a noun. Carta and Google Sheet are things; "Edit here" is a location. Suggest "Type it in".
- "Source" appears in the plan and chips ("Cap table source" aria-label), but the meta line says "Carta · as of Sep 30" and for sheets "From <sheet> · as of". Three phrasings for one fact: use "<Source> · as of <date>" for all.
- "Refresh" (Carta) vs "Re-read" (sheet) for one idea (R1). One verb, "Refresh", with the tooltip following the source.
- "Pool" (editor security) vs "Option pool" (summary tile) vs "Pool available" (table row) vs "Options granted" (row). Four names for two concepts. Use "Option pool" with "granted" and "available".
- "Invested" column header in the mockup for founders and options shows "—"; for SAFEs it shows the SAFE amount. "Invested" is fine for investors, but as the column also carries SAFE rows beside "% at cap" in the last column, readers mix "Fully diluted" with "at cap". Suspected, minor.
- "Fully diluted" is jargon for a first-time founder like Tomas; it is the standard term and appears in the tile, so keep it, but show the plain total ("10,250,000 shares") first, which the tile already does.
- "Hide amounts" is clear; whether it masks editor inputs is unspecified (PG-22).

## Verdict

acceptable, trending toward convoluted for source switching.

The typing journey itself is short in input terms; the planned 9 steps come from an explicit Save, a verification step and a mode toggle that can all go. The real friction sits one level up: a permanent three-way source control where each chip silently overwrites the table (FR-005), unresolved which source wins when Carta and a sheet coexist (FR-009), and a SAFE entry duplicated between the editor and Fundraising.

Top 3 plan changes:
1. Replace the header source chips with a meta line plus "Change source", with Undo instead of a confirm on switching.
2. Make the native table always editable with autosave and defaults (Common, company name, as-of), no Save button or unsaved prompt.
3. Remove SAFE from the editor's security list and decide one rule for which source wins when Carta is connected.
