# ux-visual V1: auth, onboarding, tour, shell, Settings, Integrations, bot settings

Inspector: uxl1-V1. Target: mock-data demo stack only (web :5381). Date 2026-10-20.
Viewports: 1440x900 and 375x812 for every page; 1920x1080 for the shell.
Method: screenshot (every image opened and read), layout-audit.js and geometry-audit.js via agent-browser eval, human-style interaction (menus, dialogs, tab focus, resize, error states).
Screenshots: /tmp/uxloop1/V1/ (outside the repo).
Notes: the first-run flow and tour used a freshly signed-up invented user (walker-v1a@northwind.example.test). OAuth "Authorize" buttons were not clicked (BLOCKED, real provider). The audit's lowContrast ratios (about 1.32 everywhere, including clearly readable text) are a script artifact on this theme and are not filed. Sidebar contents (many "(mock)" bots) are demo data and are not judged.

## Excellent as is

- Sign-in and sign-up forms: centered, clear labels, show-password, "At least 8 characters" hint, primary button is the only high-emphasis element (H1), tab order Email, Password, Show, Forgot, Continue is logical.
- App shell fits one screen at 1440x900, 1920x1080 and 375x812 with no page scroll; chat and sidebar scroll internally and the composer stays pinned (L1, L2, P1).
- Mobile navigation drawer: right size, close button, same content as desktop, composer and header clean at 375.
- Visible, high-contrast keyboard focus rings throughout; a "Skip to content" link exists.
- Bot actions menu: sensible grouping with dividers and a red Delete at the end (H2, I3).
- Pages options menu: simple checkable list; page badges (8 unread, 24 mo) give status at a glance.
- Integrations page: clear Connected / Find an app / Popular sections, status chips in words plus color, per-app next action ("Open Inbox", "Open Finance"), search and category filters, responsive from 3 columns to 1.
- Models settings copy ("The AI your bots think with. They already have one, so change this only to use another AI company or your own key.") sets the right default.
- First-run flow: lands straight in the app with Chief, a four-option question, answered choice collapses to one row, then relevant app cards: short and goal-led.
- Loading skeleton exists for the shell; sign-in errors keep entered values.
