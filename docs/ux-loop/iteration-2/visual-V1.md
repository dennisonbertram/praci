# Visual inspection V1 (session uxl2-V1), iteration 2

Scope: sign-in, sign-up, onboarding, first-run tour, app shell and sidebar, Settings, Apps (Connect apps), bot settings panel.
Target: mock-data demo stack (web :5381). Screenshots: `/tmp/uxloop2/V1/`. Viewports: 1440x900, 375x812, shell also at 1920x1080 and 1280x720.
Method: layout-audit.js and geometry-audit.js on every page and state, my own contrast pass, hover, Tab order, Escape, menus, dialogs.

Caveats:
- The demo database is shared with other inspectors. During the walk a "New Bot" appeared, Cap table was hidden in Page options, runway changed from 24 to 26 mo, and avatars switched type. Findings do not depend on those changes.
- The demo stack runs from `/Users/dennison/develop/rakazo`, which may be older than the worktree. Findings I read in the worktree code are marked with file:line.
- The audit's contrast check reports ratios of about 1.3 on sidebar text. That is a false positive (transparent backgrounds). My own pass using the composited background found no text under 4.5:1 on the screens I saw.
- Fresh users were signed up as walker-v1-N@northwind.example.test with generated passwords. The demo password was never printed.

BLOCKED / not exercised: Gmail and Google Calendar "Authorize", every app "Connect" (real OAuth). "Clear conversation" and "Forgot password?" were not triggered (destructive on shared data / needs mail). There is no model-selection onboarding step: the deployment supplies a default model and Settings > Models says so.

## Excellent as is

- Landing page and sign-in/sign-up: one focal point, one primary action, no horizontal overflow at 375px, logical Tab order (email, password, show password, forgot, submit, switch), visible focus rings.
- Onboarding choice card in the chat ("What do you want me on first?"): four plain choices with a hover state, the answered choice stays visible with a check, and the connect step stays inside the conversation instead of leaving for a wizard.
- Escape closes the tour, menus and Settings, and focus returns to the account menu button after the dialog closes.
- Settings dialog: fixed height that does not change between sections on desktop, fits at 1280x720 (40px margin top and bottom), content scrolls inside it.
- Pages menu and account menu: compact 28px rows, check marks show state, no explainer text beyond one useful hint on "Hide amounts".
- Delete account needs the current password (good error prevention).
- Apps page at 375px: single column, "Connected" cards clear, no overflow; sidebar drawer at 375px behaves like the desktop sidebar.
- Chat message hover toolbar appears without moving the layout (no shift), and is reachable by tap on mobile.
- App shell at 1440x900, 1920x1080 and 1280x720 fits one screen with page scroll 0; long lists scroll inside their panel.
